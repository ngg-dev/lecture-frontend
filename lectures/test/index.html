От HTML до пикселя

Что на самом деле происходит в браузере, пока вы смотрите на страницу, — и почему это знание меняет то, как вы пишете код.

Дек в одном HTML-файле, без сборки. Навигация: ← → пробел.
Шаг 1

Пять стадий, которые проходит каждая страница

HTML → DOM→ CSS → CSSOM→ render tree→ layout→ paint

Браузер не «рисует HTML». Он строит два дерева — структуру и стили, — сливает их, считает геометрию и только потом закрашивает пиксели.

  • DOM — дерево узлов из разметки. Его видно в DevTools, им можно управлять из JS.
  • CSSOM — то же для стилей: каскад, наследование, итоговые значения.
  • Layout — где и какого размера каждый блок. Самая дорогая стадия.
  • Paint — заливка. Здесь появляются настоящие пиксели.
Ключевая мысль: дерево отрисовки не равно DOM — узел с display: none в него не попадает.
Шаг 2

DOM — это живая структура, а не текст

Каждый вызов, меняющий разметку, порождает узлы. Они сразу становятся частью дерева — их можно найти в Elements и посчитать через childElementCount.

const p = document.createElement('p');
p.textContent = 'новый узел';
list.append(p);          // узел в дереве
console.log(list.children.length);
Работает прямо здесь
    узлов: 0
    Шаг 3

    Почему «просто поменять класс» иногда дорого

    Меняем paint

    color, background, box-shadow. Геометрия не меняется — браузер перекрашивает область и идёт дальше.

    Меняем layout

    width, margin, font-size, добавление узла в поток. Пересчитывается геометрия, часто — всего документа.

    Отсюда два практических правила: не читать геометрию в цикле после каждой записи (layout thrashing) и не вставлять разметку строкой на каждое событие ввода.

    // плохо: перестройка DOM на каждый символ
input.addEventListener('input', e => {
  list.innerHTML = items.map(i => `<li>${i}</li>`).join('');
});
    Шаг 4

    Событие: от клика до обработчика

    Событие не «приходит в кнопку». Оно идёт от корня документа вниз (capture), затем всплывает обратно (bubble). Обработчик по умолчанию срабатывает на всплытии.

    Итог

    Что забираем с лекции

    • DOM и CSSOM — два дерева, которые сливаются в дерево отрисовки.
    • Layout дороже paint: меняйте то, что не двигает геометрию, когда это возможно.
    • Событие проходит путь capture → target → bubble, и на этом строится делегирование.
    • DevTools → Performance показывает все стадии на реальном взаимодействии.
