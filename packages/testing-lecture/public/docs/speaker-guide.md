# Заметки преподавателя

**40 слайдов, 77 минут рассказа; практика отдельно 20 минут.** Оформление продолжает TS-лекцию: синяя сетка, контурные карточки, жёлтая линия главного вывода. Навигация общая, без вложенных шагов. N открывает отдельную заметку текущего слайда.

## Маршрут и время

- Есть магазин. Есть риск. — 11 минут: открыть магазин, показать корректное изменение цены, затем объяснить Number('') и отличие теста от типов.
- Проверяем правило — 21 минута: runner, контракт, AAA, RED, GREEN, границы, matcher-ы и живой эксперимент.
- Проверяем интерфейс — 15 минут: проблема подключения формы, DOM, ввод, async, mocks, отказ/повтор.
- Проверяем путь пользователя — 16 минут: сборка, браузер, честная граница e2e, locator/expect, HTTP 500, изоляция и trace.
- Закрепляем и запускаем — 14 минут: стратегия, coverage, условия практики, проверка полезности теста, CI, вопросы и итог.

Сами 20 минут самостоятельной работы вставьте после слайда `#practice-task` либо после рассказа. Обсуждение карточек вопросов можно сократить, но не опускать отказ/повтор и границу mock API.

## До пары

1. Из пакета выполнить `npm ci` и `npm run check`.
2. Из корня собрать курс и запустить сервер по README. Отдельно выполнить `npm run test:e2e` из пакета.
3. Открыть деку и обычный `shop/`. Не открывать `shop/?mode=api` как самостоятельный Pages-demo: режим требует перехвата тестом.
4. Проверить управление на используемом проекторе; длинный код скроллится внутри блока, слайд — вертикально.
5. Подготовить исходники `tests/model.test.ts`, `tests/PriceEditor.test.tsx`, `e2e/shop.spec.ts`. Слайды — ключевые фрагменты, эти файлы — полный исполнимый код.

## Обязательные вопросы

- Почему 0 разрешён, а пустая строка нет? Почему `if (!price)` здесь неверен?
- Что ловит TypeScript, чего не ловит? Почему тест не заменяет runtime if?
- Почему mock onSave не проверяет настоящий сервер?
- Чем `await expect(locator)` отличается от `expect(await locator.textContent())`?
- Что означает зелёный тест, если из обработчика удалили действие и он всё равно зелёный?

## Демонстрации

`#unit-lab`: ошибочная версия → запустить → увидеть FAIL; исправленная → все PASS. Это реальные вызовы, не Jest в браузере. Для runner открыть терминал и npm test.

`#component-lab`: корректная цена → успех; пустая → alert; включить отказ → alert; повтор → успех. Отказ локального callback — не реальный HTTP.

`shop/`: добавить книгу, поменять цену, увидеть обновлённый итог. Хранение локальное, reload сбрасывает данные.

В терминале временно убрать проверку пустоты и показать красный unit. Затем вернуть код и повторить. Намеренные поломки не оставлять в основной ветке. Скриншот или «собралось» не заменяют реальный запуск.

## Что оставить за рамками

Не превращать лекцию в обзор Jest/Cypress/MSW, не заставлять настраивать Docker/БД/CI. Сначала одно правило, затем одна форма, затем один пользовательский путь. Порог coverage не задаём: важнее тест, реально ловящий нарушение.
