# Лабораторная работа 8

## Unit и e2e-тестирование

Продолжите **свой проект из лабораторной №7**. Добавьте тесты к существующему коду,
не переписывайте приложение с нуля.

**Срок:** 2 недели от лекции 07.11 — до 21.11.2026.

**На 3 — тесты синхронных функций в Jest. На 4 — дополнительно тесты асинхронных
функций в Jest. На 5 — дополнительно тесты сайта через Playwright.**
Оценка 4 включает всё на 3, оценка 5 — всё на 4.

## Удовлетворительно — 3

- Напишите тесты на Jest для синхронных функций своего проекта — тех, которые
  сразу возвращают результат. Например: подсчёт суммы, фильтрация списка,
  проверка введённого значения.
- Проверьте, что функции возвращают правильный результат для обычных данных.
  Добавьте подходящие для этих функций случаи: например, пустой список или неверный ввод.
- Тесты должны вызывать настоящие функции проекта и сравнивать результат с ожидаемым.
  Команда `npm test` запускает тесты, все проверки проходят.

**На защите:** покажите функции, объясните, что проверяют тесты, и запустите их.
Вопросы: «Почему эта функция синхронная?», «Какой результат вы ожидаете и почему?».

## Хорошо — 4

Выполните всё на «Удовлетворительно», а также:

- Напишите тесты на Jest для асинхронных функций своего проекта — например,
  загрузки списка или сохранения изменений на сервере.
- Проверьте два варианта: операция выполнена успешно и произошла ошибка.
  Тест должен дождаться завершения операции через `await` и проверить результат.
- Ответ сервера можно заменить заранее заданными данными в тесте — это mock.
  При этом проверяйте саму функцию загрузки или сохранения, а не подменяйте её.

**На защите:** покажите тесты успешной операции и ошибки, объясните использование `await`.
Вопросы: «Чем эта функция отличается от синхронной?», «Что заменяет mock в вашем тесте?».

## Отлично — 5

Выполните всё на «Хорошо», а также:

- Напишите тесты на Playwright, которые открывают сайт в браузере и выполняют
  действия пользователя. Например: добавить товар в корзину, изменить значение
  в форме или перейти на страницу с подробностями.
- Проверяйте результат действия на странице: товар появился в корзине,
  новое значение показано или открылась нужная страница. Одного открытия сайта недостаточно.
- Добавьте команду `npm run test:e2e` и опишите в README, как запустить сайт и эти тесты.
  Все тесты должны проходить и не зависеть от порядка запуска.

**На защите:** запустите тесты Playwright и объясните, какие действия пользователя они проверяют.
Вопросы: «Что проверяет браузерный тест, чего не проверяет тест функции?»,
«Как тест понимает, что действие завершилось успешно?».

## Общие условия

- Сохраняйте работающий проект, TypeScript и команды `npm run typecheck`, `npm run build`.
- Не подменяйте проверяемую функцию, не отключайте тесты и не меняйте ожидаемый ответ
  только ради успешного запуска.
- Каждый тест готовит свои данные. Не используйте произвольные паузы вместо ожидания результата.
- Если ответы сервера подменены, укажите это в README: настоящий сервер и БД такой тест не проверяет.
- Количество тестов и процент покрытия не заданы. Важно проверить выбранные функции
  и действия по условиям своего уровня.
- Отдельные отчёты, trace и демонстрация намеренной поломки не обязательны.
  Настраивать CI, Docker и собственную БД не нужно.

## Что сдать

1. Ссылку на репозиторий или PR с продолжением проекта №7, тестами и настройками.
2. README: какие функции или действия проверяются и какими командами запускать тесты.
3. Вывод успешного запуска `npm test`, `npm run typecheck`, `npm run build`.
   На 5 дополнительно — вывод `npm run test:e2e`.

Не включайте в репозиторий `.env`, секреты и `node_modules`.

## Настройка инструментов

Установка в своём проекте:

```sh
npm install -D jest @jest/globals @types/jest \
  babel-jest @babel/core@7 @babel/preset-env@7 \
  @babel/preset-typescript@7
# На 5 дополнительно:
npm install -D @playwright/test
npx playwright install chromium
```

Добавьте в `package.json` команду `"test": "jest"`;
на 5 — `"test:e2e": "playwright test"`. Сохраните lockfile.

```js
// jest.config.cjs
module.exports = {
  testEnvironment: 'node',
  testMatch: ['<rootDir>/tests/**/*.test.ts'],
  transform: { '^.+\\.[jt]s$': 'babel-jest' },
  clearMocks: true,
  restoreMocks: true,
};
```

```js
// babel.config.cjs
module.exports = {
  presets: [
    ['@babel/preset-env', { targets: { node: 'current' }, modules: 'commonjs' }],
    '@babel/preset-typescript',
  ],
};
```

API Jest импортируйте из `@jest/globals`. Babel убирает аннотации типов,
но не проверяет их: для этого оставьте `tsc --noEmit`.

Для Playwright используйте `testDir: './e2e'` и `baseURL` своего сайта.
Сервер можно запускать отдельно по инструкции в README или автоматически
через Playwright `webServer`. Jest ищет файлы только в `tests/`, Playwright — в `e2e/`.

## Как проверять (для проверяющего)

В репозитории студента:

```sh
npm ci
npm run typecheck
npm test -- --runInBand
npm run build
# На 5 дополнительно:
npx playwright install chromium
# Запустите сайт по инструкции из README, если он не стартует автоматически.
npm run test:e2e
```

Убедитесь, что тесты импортируют функции рабочего проекта и проверяют результаты.
Проверьте, что проверки не отключены:

```sh
grep -RInE '(test|it|describe)\.(skip|only|todo)|waitForTimeout|@ts-ignore|as unknown as' src tests e2e
```

На 3/4 папки `e2e/` может не быть — исключите её из команды.
Совпадение в комментарии не является нарушением: прочитайте найденные строки.

| Оценка | Что проверять | Что спросить |
| --- | --- | --- |
| 3 | Jest проверяет синхронные функции проекта, обычные данные и подходящие особые случаи | Почему функция синхронная? Какой ответ ожидается? |
| 4 | Всё на 3; Jest проверяет успех и ошибку асинхронных функций, результат ожидается через await | Зачем await? Что заменяет mock? |
| 5 | Всё на 4; Playwright выполняет действия на сайте и проверяет видимый результат | Что проверяет браузер? Как определяется успех действия? |
