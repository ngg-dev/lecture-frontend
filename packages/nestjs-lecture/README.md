# NestJS: бэкенд на TypeScript

27 слайдов, 65 минут, до 5 минут на вопросы. На примере книжного магазина разбираем, как устроить бэкенд на TypeScript с NestJS.

## Маршрут

- React-магазин, общие библиотеки и типы. TypeScript на сервере, Node.js и NestJS.
- Сходства со Spring Boot. Общая схема ролей React, контроллера и сервиса. Граница модуля на примере заказов и каталога.
- MongoDB с нуля. Документ заказа и интерактивная схема оформления от интерфейса до записи.
- Ошибки API и состояния интерфейса во время запроса.
- Основной сервер, BFF и выделенный сервис. BFF Яндекс.Маркета, оплата Pix в Getnet и загрузка фото в Immich.

На слайдах используются схемы. Рабочий пример использует JavaScript, NestJS и MongoDB. Общий контракт TypeScript/JSDoc доступен в `contracts/` и `examples/`.

## Просмотр и исходники

Из корня: `npm run serve`. Открыть http://127.0.0.1:4170/lectures/nestjs-lecture/.

`src/content.js` — содержание, тайминг, заметки, источники. `src/index.html` и `src/styles.css` — оболочка. `src/diagrams.js` — схемы. `src/shop.jsx` — React-магазин. `api/src/` — настоящий NestJS API. `contracts/book.d.ts` и `examples/shared-types.*` — пример общего контракта.

```sh
cd packages/nestjs-lecture
npm ci
npm run check
npm run build
```

`deck/` — готовая автономная презентация с bundled React, без CDN. JS и CSS имеют хеш содержимого в имени файла, чтобы после обновления не запускался старый скрипт из кеша. Корневой `npm run build` собирает и копирует её в `lectures/nestjs-lecture/`. Для точечного обновления из корня после сборки пакета:

```sh
cp -R packages/nestjs-lecture/deck/. lectures/nestjs-lecture/
```

Публикация остаётся существующей: GitHub Pages, `main`, `/`. Изменения не отправляются автоматически этим пакетом.

## Отдельный пример и API

В презентации магазин использует данные в памяти браузера. На странице `demo.html` доступны изменение цены и переключение на API. В локальном режиме все действия выполняются в React, а обновление страницы сбрасывает изменения. Поиск и категории фильтруют загруженный список на клиенте также в API-режиме; серверные фильтры отдельно демонстрируются через HTTP-запросы.

Для реального API требуется MongoDB. Например, при работающем Docker:

```sh
docker run --name lecture-books-mongo -p 127.0.0.1:27017:27017 \
  -v lecture-books-data:/data/db -d mongo:8
# При повторном старте уже созданного контейнера: docker start lecture-books-mongo
npm run seed
npm run api
```

По умолчанию Mongo URI — `mongodb://127.0.0.1:27017/bookshop`, API — `http://127.0.0.1:3000`. Можно задать `MONGO_URI`, `PORT`, `FRONTEND_ORIGIN` в окружении. React-демо ожидает API на порту 3000 и origin `http://127.0.0.1:4170`. Демонстрируйте реальный API с локальной HTTP-страницы: HTTPS-хостинг может ограничивать запросы к localhost.

Seed использует `$setOnInsert`, поэтому не сбрасывает ранее изменённые цены. Запустите API и нажмите «Подключить API» на странице `demo.html`. Отказ подключения показывает ошибку и повтор; автоматической подмены ответов локальными данными нет. PATCH меняет только цену. Идентификаторы в API — строки; внутренние поля Mongo в DTO не передаются.

Это учебный локальный API без пользователей и авторизации. Администраторское изменение цены не предназначено для публичного развёртывания. Корзина остаётся на клиенте; заказ и оплата не реализованы.

## Проверки

`npm run check` проверяет маршрут, тайминги и наличие заметок/источников, компилирует JavaScript-декораторы и запускает HTTP-тесты настоящего Nest-приложения с подменённой моделью БД. Проверяются фильтры, параметры, 400/404, контракт цены, DTO, PATCH и CORS. Это не интеграционный тест MongoDB: для проверки хранения запустите пример с настоящей БД, перезапустите API и повторите GET.

Управление: стрелки, Page Up/Down, Home/End; O — содержание, N — заметки, F — полный экран, Escape — закрыть панели. Полный сценарий доступен по `deck/docs/speaker-guide.html`, копия включена в опубликованную деку. На узком экране есть вертикальная прокрутка; ввод и кнопки не перехватываются навигацией.
