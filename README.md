## Исходники и структура

- `packages/<имя-лекции>/` — полная копия исходного репозитория, включая документацию, примеры, лабораторные, PDF и исходные lockfile.
- `lectures/<имя-лекции>/` — готовые статические презентации для GitHub Pages. Эти файлы хранятся в Git: после правки исходников пересоберите их перед push.
- `course.json` — порядок курса, команды проверки и каталоги результата сборки.
- `migration-sources.json` — неизменяемое свидетельство первоначального переноса: исходные репозитории, commit и SHA-256 каждого перенесённого файла. При дальнейших правках лекций этот файл не обновляют.
- `Лабораторная работа 7.md` и `.pdf` — общие материалы, сохранены на прежнем месте.
- Лабораторная 6, PDF и архив API — в `packages/react-state-managers/`, `output/` внутри этой папки.
- PDF вводной — `packages/it-lecture/lecture/frontend-talk.pdf`.

Оригинальные отдельные репозитории не удалены и не изменены. Внутренние README и workflow скопированы как часть исходников: их прежние адреса относятся к отдельным репозиториям. Вложенные `.github/workflows/` GitHub не запускает; единственный источник Pages здесь — `main`, каталог `/`.

## Просмотр и разработка

Для просмотра опубликованного сайта ничего устанавливать не нужно. Для локального просмотра готовых лекций:

```sh
npm run serve
```

Откройте <http://127.0.0.1:4170/>. Нужен Python 3.

Для разработки нужны Node.js 22+ и npm:

```sh
npm run setup
npm run check
npm run build
npm test
npm run serve
```

У каждой лекции сохранены собственные зависимости и lockfile — версии React и других библиотек не принудительно объединены. Команды доступны и отдельно, например:

```sh
cd packages/ts-lecture
npm ci
npm run check
npm run build
```

После отдельной сборки выполните `npm run build` **из корня**, чтобы обновить опубликованную копию в `lectures/`.

`npm test` проверяет структуру свидетельства миграции, все текущие записи каталога, ссылки на деки и локальные пути ресурсов. Исходные пять лекций должны оставаться в прежнем относительном порядке; новые лекции можно добавлять между ними или после них. Для каждой записи проверяются уникальный локальный `id`, непустые `title` и `summary`, относительный `output` без выхода из пакета и булевы `check` и `build`. Тесты не сравнивают рабочие исходники с первоначальными SHA-256: обычные правки лекций разрешены. Регрессии проверяются в изолированных временных Git-репозиториях, которые удаляются после тестов.

Историческая побайтовая проверка переноса запускается отдельно и не входит в шаблон `tests/*.test.mjs`:

```sh
npm run verify:migration
```

Команда запускает `tests/migration.snapshot.mjs`: через `git log --all --reverse` находит самый ранний commit с `migration-sources.json`, затем читает свидетельство и импортированные файлы именно из этого commit через `git show`, а не из рабочей папки или последнего commit. До первого commit миграции используется staging index: сначала добавьте в него свидетельство и исходный импорт. Проверка также требует, чтобы рабочий `migration-sources.json` побайтово совпадал с историческим. Не меняйте в нём хеши или commit вслед за правками исходников — это уничтожило бы связь с исходным переносом. Для проверки нужна локальная Git-история первоначального импорта, не shallow-копия, обрезанная после него.

## Публикация

Pages уже настроен на `main` и `/`. После проверки и сборки коммитьте исходники и готовые файлы из `lectures/`, затем push. Второго деплой-workflow нет; `.nojekyll` сохраняет готовые файлы без обработки Jekyll.

При добавлении лекции поместите исходники в `packages/<id>/`, добавьте запись со всеми полями `id`, `title`, `summary`, `output`, `check`, `build` в `course.json` и ссылку `lectures/<id>/` на главной, затем выполните `npm run setup`, `npm run check`, `npm run build` и `npm test`. Не удаляйте и не меняйте взаимный порядок исходных пяти записей; `migration-sources.json` не дополняйте. У `react-lecture` нет отдельной команды `check`, поэтому корневой `npm run check` выполняет для неё `build`. Для самостоятельной статической деки вне каталога можно сохранить существующий формат `lectures/<тема>/index.html` без сборки.
